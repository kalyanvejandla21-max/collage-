Slide 02 / Problem Statement

Problems with Conventional Examination Systems

Limitations of Basic Systems
  • Manual Preparation: Time-consuming manual question-paper creation by faculty.
  • Predictable Sequences: Students receive identical question orders, promoting unfair practices.
  • Assessment Decay: Repeated static questions reduce overall test effectiveness.
  • Grading Delays: Manual evaluation introduces human errors and slow score release.
  • Zero Monitoring: Students can switch tabs or leave exam windows undetected.
Problem → Challenges → Need Diagram
  • 1. Manual Work: Paper creation & manual grading burden faculty resources.
  • 2. Repetition: Static question papers facilitate cheating during tests.
  • 3. Security Issues: Unrestricted tab switching & window blur.
  • 4. Delayed Results: Lack of automated real-time score publishing.
CORE MISSION REQUIREMENT

"There is a need for a centralized, automated and secure online examination platform that can generate randomized question papers, monitor examination behavior and evaluate answers instantly."

Slide 04 / Question Randomization

Randomized MCQ System & Key Features

Fisher-Yates Question Randomization
  • Subject Question Banks: Maintained for subjects like Computer Networks & Quantum Computing.
  • 20-Question Extraction: Exactly 20 questions chosen randomly with zero duplicates.
  • Fisher-Yates Shuffle Algorithm: Applied for unbiased random ordering of questions & options A, B, C, D.
  • Correct Answer Preservation: Internal mapping remains locked to original correct choice despite option shuffling.
  • Unique Exam Instance: Every student receives a custom, non-replicable question paper.
Key Examination Engine Features
  • 30-Minute Timer: Live countdown with automatic force submission on timeout.
  • Question Palette: Visual status indicators for Answered vs Unanswered questions.
  • Auto-Save Engine: Real-time background persistence of student selections.
  • Review Unanswered: Easy filtering to re-check skipped questions before submitting.
  • Instant Result: Automated score calculation upon test completion.
Slide 05 / Exam Security

Exam Security & Active Monitoring Protocols

Browser Security Mechanisms
  • 1. Fullscreen Mode: Browser requests fullscreen on start. Exit triggers warning prompt & logs violation.
  • 2. Tab Switch & Focus Detection: Detects window blur, tab switching, or browser losing focus.
  • Web Security APIs: Fullscreen API (`fullscreenchange`), Page Visibility API (`visibilitychange`), Window Blur/Focus events.
  • 3-Tier Violation Protocol: 1st: Warning → 2nd: Strong Warning → 3rd: Final Warning.
  • Boundary Note: Clearly specifies browser-level monitoring (does not track external physical hardware).
